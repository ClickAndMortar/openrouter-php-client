§ 02 — WHAT WAS BLOCKING IT

Three primitives, all now in place

The transporter handled exactly one shape — a JSON body in, a JSON body out. Wave 1 added the two that were missing; the third turned out to need only event classes.delivered · September 3, 2026

1 solved · 2 ops Payload::upload()

Multipart request bodies

The enum case existed and nothing referenced it; all five Payload factories hardcoded ContentType::JSON. A sixth factory now builds an RFC 7578 body from an UploadedFile plus scalar and repeated name[] fields.

// src/Enums/Transporter/ContentType.php:13 — declared, never referenced case MULTIPART = 'multipart/form-data'; // src/ValueObjects/Transporter/Payload.php — all five factories hardcode JSON public static function list(string $resource, array $parameters = []): self { return new self(ContentType::JSON, Method::GET, ...); } public static function create(string $resource, array $parameters): self { return new self(ContentType::JSON, Method::POST, ...); }
unblocked

POST /files and POST /audio/transcriptions — and with them the whole Files family, since upload is its entry point.

2 solved · 4 ops requestContent()

Raw / binary response bodies

Four endpoints return bytes rather than JSON: synthesized speech, a video file, and two file-content downloads. requestObject() decoded unconditionally. A sibling requestContent() now returns a BinaryResponse — raw bytes, the upstream Content-Type, and saveTo() — while still raising API errors, which arrive as JSON even here.

// src/Transporters/HttpTransporter.php:74 — every response is decoded as JSON $contents = $response->getBody()->getContents(); $data = json_decode($contents, true, flags: JSON_THROW_ON_ERROR); // There is no accessor that hands back the raw bytes, so an audio/*, // video/mp4 or application/octet-stream body throws before it reaches // the caller.
unblocked

POST /audio/speech, GET /files/{id}/content, GET /videos/{jobId}/content, GET /containers/…/content.

3 solved · 1 op ImageStreamEvent

SSE outside chat

POST /images is the only new endpoint that streams, and the prediction held: no transport work was needed. requestStream() already returns a raw PSR-7 response and StreamResponse is generic over an event class, so it took three typed frames — image_generation.completed, .partial_image, .text_chunk — plus the usual base-class fallback for frames OpenRouter adds later.

§ 03 — HOW IT SHIPPED

Four waves, one commit each

Only wave 1 was a prerequisite; the rest were additive and independently shippable, which is why each landed as its own commit with the suite green.63 operations · 4 waves · all delivered

✓ waves 1–4 delivered 63 endpoints +254 tests

Transport primitives first, then everything on top

Wave 1 shipped Payload::upload() with an UploadedFile part and requestContent() returning a BinaryResponse, and was tested on its own before any resource used it. Wave 2 built the media surface on top; waves 3 and 4 needed no transport work at all, exactly as this report predicted when it was first written.

methodology

Operations extracted from the live OpenAPI document and diffed against the SDK’s typed resources. Transport verdicts read from each operation’s declared request and 2xx response content types, then checked against src/Transporters/HttpTransporter.php and src/ValueObjects/Transporter/Payload.php. Revision 3 records all four waves as delivered; the family table keeps the original grouping so the revisions stay comparable. No effort estimates in days — sequencing is driven by operation count, dependency and transport need.
